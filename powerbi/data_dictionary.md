# FraudLens — Power BI Enterprise Data Dictionary

## 1. Data Model Architecture Overview

FraudLens implements a performance-optimized **Star Schema** architecture designed for interactive BI analytics over the 6.36M transaction PaySim dataset. The architecture provides sub-second visual responsiveness by pairing pre-aggregated fact tables for executive, financial, and temporal dashboards with high-fidelity forensic extracts and machine learning model evaluation tables.

## 2. Table Specifications & Data Dictionaries

### Table 1: `Summary_Channel_KPIs` (Aggregated Fact Table — Executive & Financial View)
Granularity: One record per transaction type (5 rows total). Directly matches Phase 4 SQL ground truth.

| Field Name | Data Type | Analytical Description & Business Meaning |
| :--- | :--- | :--- |
| `transaction_type` | String (PK) | Transaction method/channel (`TRANSFER`, `CASH_OUT`, `PAYMENT`, `CASH_IN`, `DEBIT`). |
| `total_transactions` | Whole Number | Total transaction count conducted across the 31-day simulation cycle. |
| `total_volume_usd` | Currency ($) | Aggregate monetary transacted volume in USD. |
| `avg_transaction_amount` | Currency ($) | Arithmetic mean monetary value per transaction. |
| `fraud_transactions` | Whole Number | Count of confirmed, ground-truth fraudulent transactions. |
| `fraud_exposure_usd` | Currency ($) | **Fraud-Labeled Exposure**: Total monetary volume associated with confirmed fraud incidents. |
| `fraud_rate_pct` | Percentage (%) | Incidence rate of fraud: `(fraud_transactions / total_transactions) * 100`. |
| `legitimate_transactions`| Whole Number | Count of confirmed legitimate (non-fraud) transactions. |
| `legitimate_volume_usd`| Currency ($) | Monetary volume of legitimate transactions. |
| `avg_fraud_amount` | Currency ($) | Average ticket size of fraudulent transactions ($1,467,967.30). |
| `avg_legitimate_amount` | Currency ($) | Average ticket size of legitimate transactions ($178,197.04). |
| `flagged_fraud_count` | Whole Number | Count of transactions triggered by the heuristic rule (`amount > 200,000`). |
| `true_positives` | Whole Number | Legitimate detections where heuristic flag accurately identified confirmed fraud (16). |
| `false_positives` | Whole Number | False alarms generated by the heuristic rule (0). |
| `false_negatives` | Whole Number | Missed fraud events bypassed by the heuristic rule (8,197). |
| `true_negatives` | Whole Number | Legitimate transactions correctly unflagged (6,354,407). |

### Table 5: `FactFraudInvestigation_Extract` (Forensic Drill-Down Fact Table)
Granularity: 20,865 rows containing **all 8,213 confirmed fraud incidents (100% recall)** plus high-risk anomalies and stratified legitimate reference transactions.

| Field Name | Data Type | Analytical Description & Business Meaning |
| :--- | :--- | :--- |
| `transaction_id` | Whole Number (PK)| Unique surrogate database transaction identifier. |
| `step` | Whole Number (FK)| Simulation hourly timeline step. |
| `transaction_type` | String (FK) | Payment channel (`TRANSFER`, `CASH_OUT`, etc.). |
| `amount` | Currency ($) | Transaction monetary amount. |
| `origin_account` | String | Origin customer account ID (e.g. `C123456789`). |
| `orig_old_balance` | Currency ($) | Pre-transaction balance of origin account. |
| `orig_new_balance` | Currency ($) | Post-transaction balance of origin account. |
| `dest_account` | String | Recipient account ID (e.g. `M987654321`, `C456789123`). |
| `dest_old_balance` | Currency ($) | Pre-transaction balance of destination account. |
| `dest_new_balance` | Currency ($) | Post-transaction balance of destination account. |
| `is_fraud` | Binary (0/1) | Ground-truth fraud label. |
| `is_flagged_fraud` | Binary (0/1) | Rule-based heuristic flag. |
| `orig_balance_error` | Currency ($) | Discrepancy: `(orig_old_balance - amount) - orig_new_balance`. |
| `dest_balance_error` | Currency ($) | Discrepancy: `(dest_old_balance + amount) - dest_new_balance`. |
| `is_drainage` | Binary (0/1) | Flag: 1 if origin account was completely emptied to $0.00. |
| `risk_score` | Whole Number | Behavioral risk score (0 to 100). |
| `risk_category` | String (FK) | Risk tier: Critical, High, Medium, Low. |
| `investigation_typology`| String | Narrative forensic tag explaining observed anomaly pattern. |

### Dimension Tables (11, 12, 13)
- **`DimTransactionType`**: Channel master dimension (`TRANSFER`, `CASH_OUT`, `PAYMENT`, `CASH_IN`, `DEBIT`) with risk ratings.
- **`DimTime`**: 743-step simulation calendar with hour brackets (`Night`, `Morning`, `Afternoon`, `Evening`) and business hour flags.
- **`DimRiskTier`**: Behavioral risk scoring tiers (`Critical`, `High`, `Medium`, `Low`) with SLA triage action codes (`ACT_FREEZE`, `ACT_REVIEW_PRIORITY`, etc.).
